# 야간 관리가 강화되어야 할 지하철역

> **야간(20~04시) 이용률이 높으면서 배후 유동인구까지 많은 역은 야간 운영과 안전 관리를 특별히 강화해야 한다.**

서울 지하철 시간대별 승하차 데이터와 서울 생활인구 데이터를 결합해, 특별 관리가 필요한 역의 우선순위를 제시하는 미니 프로젝트입니다.

## 우선순위 선정 규칙

1. 월 승하차 **10,000명 미만** 역은 제외 — 표본이 작으면 비율이 튑니다(월 3명 중 1명이 야간이면 33%가 되어 1위가 됩니다).
2. 남은 역 중 **야간이용률 상위 10%**만 후보로 추립니다. (202607 기준 16.3% 이상, 52개 역)
3. 후보를 **배후 행정동의 유동인구가 많은 순**으로 세웁니다.

기준값은 `app/repository.py`의 `NIGHT_QUANTILE`(기본 0.90)과 사이드바의 "최소 월 승하차 인원"으로 조정합니다.

## 아키텍처

`mini_project2_guide.md`의 3계층 구조를 따릅니다. `collector/`와 `app/`은 서로를 import하지 않고, **DB 스키마만 공유**합니다.

| 계층 | 디렉터리 | 역할 | DB 권한 |
|---|---|---|---|
| 수집 | `collector/` | Open API 호출 · 정제 · 적재 (`python -m collector`) | 쓰기 |
| 저장 | `db/` | 스키마, 마트 집계 SQL | — |
| 대시보드 | `app/` | 조회 · 시각화 (`streamlit run app/main.py`) | 읽기 전용 |

## 사용 데이터

| 출처 | 서비스명 | 내용 |
|---|---|---|
| 서울 열린데이터광장 | `CardSubwayTime` | 지하철 호선별 역별 시간대별 승하차인원 (월 단위) |
| 서울 열린데이터광장 | `ppsLocalResd` | 집계구 단위 서울 생활인구(내국인) |
| 서울 열린데이터광장 | `subwayStationMaster` | 지하철역 위경도 (역↔행정동 매핑용) |
| [vuski/admdongkor](https://github.com/vuski/admdongkor) | 행정동 경계 GeoJSON | 좌표 → 행정동코드 판정용 (최초 1회 34MB 캐시) |

지하철 데이터에는 행정동코드가 없고 생활인구는 행정동 단위라 그대로는 조인되지 않습니다. **역 좌표를 행정동 경계와 point-in-polygon으로 대조**해 `dim_station`을 자동 생성하여 잇습니다. 수동 매핑 작업은 없습니다.

## 실행 순서

```bash
# 1. 환경설정
cp .env.example .env          # PowerShell: copy .env.example .env
pip install -r requirements.txt

# 2. DB 초기화 (MariaDB가 로컬에서 실행 중이어야 함). 여러 번 실행해도 안전합니다.
mysql --default-character-set=utf8mb4 -u root -p < db/schema.sql

# 3. 데이터 수집 (역-행정동 매핑 → 지하철 → 생활인구 순으로 진행)
python -m collector

# 4. 마트 재생성 (수집 후 매번 실행)
mysql --default-character-set=utf8mb4 -u root -p mini_project2 < db/build_mart.sql

# 5. 대시보드 실행
streamlit run app/main.py
```

> `--default-character-set=utf8mb4`를 빼면 한글 데이터에서 `ERROR 1366`이 납니다.

로컬 편의를 위해 `Makefile`(`make init/collect/mart/dash`)과 Windows용 `commands.ps1`(`.\commands.ps1 init` 등)을 두었지만, 두 파일은 `.gitignore` 대상이라 저장소에는 포함되지 않습니다. 클론 후에는 위 명령을 직접 사용하세요. (PowerShell은 `<` 리다이렉션을 지원하지 않아 `mysql -e "source db/schema.sql"` 형태를 써야 합니다.)

## 설정 (`collector/config.py`)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `TARGET_USE_MM` | 최근 3개월 | 지하철 수집 대상 월. API가 매월 5일 전월분을 갱신하므로 2개월 여유를 둡니다. |
| `NIGHT_HOURS` | `{20,21,22,23,0,1,2,3,4}` | 야간 정의(20~04시). **`db/build_mart.sql`의 CASE 조건과 항상 같아야 합니다.** |
| `COLLECT_LIVING_POP` | `True` | 생활인구 수집 여부 |
| `LIVING_POP_MAX_PAGES` | `None`(전체) | 페이지 제한. 1페이지 = 1,000행 |
| `BUILD_DIM_STATION` | `True` | 역-행정동 매핑 갱신 여부 |

인증키는 일일 호출 한도가 있습니다. 생활인구 전체 수집은 약 459회 요청(요청 간 0.5초, 약 4분)이므로, 처음에는 `LIVING_POP_MAX_PAGES = 3` 정도로 확인한 뒤 전체를 받으세요.

## 대시보드 화면

- **KPI**: 분석 대상 역 수 / 평균 야간이용률 / 1순위 역 / 기준월
- **요약**: 상위 10개 역을 역명(크게)과 노선명(작게) 카드로 표시. 수치는 싣지 않습니다.
- **역 랭킹**: 우선순위 순 막대(길이 = 야간이용률) + 상세 표(역·호선·기준월·야간이용률) + CSV 다운로드
- **시간대 히트맵**: 상위 역들의 시간대(0~23시)별 승하차량 히트맵
- **월별 추이**: 역을 골라 월별 야간이용률 추이와 시간대별 승/하차 라인차트

사이드바에서 기준월, 표시할 역 수, 최소 월 승하차 인원을 조정합니다.

## 데이터를 다루며 확인한 함정

실제 데이터에서 겪은 문제와 대응입니다. 자세한 스키마 설명은 [db/README.md](db/README.md)에 있습니다.

- **환승역이 호선별로 쪼개져 있음** — `홍대입구`가 2호선·경의선·공항철도로 3행. 역 단위 분석이 목적이라 `transform.py`에서 승하차를 합산하고 호선명을 공백으로 이어 붙입니다(`2호선 경의선 공항철도 1호선`). 620여 개 호선×역 → 528개 역.
- **원본에 중복이 있는 달** — 202607은 API가 621개 역을 2번씩 내려줍니다. 정제 단계에서 제거하고 로그에 경고를 남깁니다.
- **생활인구 API는 날짜 필터를 받지 않음** — 경로에 날짜를 붙이면 `INFO-200`이 돌아옵니다. 파라미터 없이 호출해 "가장 최근 1일치" 전체 스냅샷(약 458,000행)을 페이징으로 받습니다. 메모리 문제를 피하려 페이지 단위로 즉시 적재합니다.
- **행정동코드는 8자리** — `11110515` 형태입니다. 10자리 행정표준코드를 넣으면 조인이 오류 없이 조용히 실패합니다. GeoJSON에서 맞는 필드는 `adm_cd`(424개 중 32개만 일치)가 아니라 **`adm_cd2`의 앞 8자리**(416개 일치)입니다.
- **역명 표기** — API는 `홍대입구`처럼 '역' 접미사 없이 내려줍니다. `subwayStationMaster`도 같은 표기라 그대로 조인됩니다.


## 알려진 한계

- **유동인구는 행정동 단위**라 같은 동에 있는 역은 값이 같습니다(강남·신논현 = 역삼1동, 여의나루·여의도·샛강 = 여의동). 역별 변별력이 아니라 배후 상권 규모 지표로 해석해야 합니다.
- **생활인구는 최신 1일치 스냅샷**입니다. API가 과거 날짜를 제공하지 않아 월별 추이는 지하철 데이터에만 있습니다. 요일·계절 효과는 반영되지 않습니다.
- **서울 밖 역은 순위에서 빠집니다.** 528개 역 중 299개만 서울 행정동에 매핑됩니다(7호선 인천 구간, 1호선 경기 구간 등은 서울 생활인구 데이터가 없습니다).
- 행정동 경계(2025-04)와 생활인구 데이터의 행정동이 8개 어긋납니다(424개 중 416개 일치). 해당 동의 역은 유동인구가 비어 순위에서 제외됩니다.
